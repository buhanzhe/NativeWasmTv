# 真实站点脚本：解析耗时比较

2026-09-10。三平台统一ARM32，央视网CCTV-2、广西综艺旅游，使用cjs仓库原始main.js；每引擎4轮，首轮单列，后3轮平均。轮次交替引擎顺序，关闭结果缓存，真实在线HTTP；两引擎调用相同Ku9HttpClient。

QuickJS经现有NativeQuickJs桥接；WebView测试适配器经prompt转发到后台HTTP线程。这衡量这两个调用实现，不是两种引擎的纯执行时间。WebView初始化、脚本读取在调用计时外。网络列包含DNS/TLS/连接复用/服务器响应/读取，差值还包含MD5桥接、线程调度和JS等，不能把差值全部称为JS耗时。

## 央视频

原始央视频并非main(item)：授权HTML、XHR、Cookie、时间校准和原生签名构成完整链路。独立QuickJS不具备这些浏览器接口，未修改站点协议来人为构造对比，不提供QuickJS端到端数字。

WebView测试使用应用原有YangshipinWebResolver、完整CCTV-2频道配置（PID 600001800 / streamId 2024075401），挂载到实际空白Activity窗口，不启动播放器。每轮新建resolver并使用独立偏好设置，避免URL/服务器时钟缓存命中。插件安装与原生加载在计时外，HTTP连接池和系统缓存可能复用。

- 4.0.4：三次 [574.4, 290.1, 319.2] ms；后两次平均 304.6 ms。均返回可用URL。
- 4.4：三次 [986.9, 539.2, 554.6] ms；后两次平均 546.9 ms。均返回可用URL。
- 7.1.1：未获得成功结果。auth HTTP后已记录校时，刷新后未完成回调，已终止测试；不能把等待时间作为正常解析耗时。诊断日志保存在ysp-711-diagnostic.log。尚未定位为测试窗口生命周期问题还是实际WebView链路问题。

结论：真实小脚本的非网络成本仅几到几十毫秒，不能用计算微基准的倍数推算换台收益。当前数据不支持仅为性能把全部CJS改回WebView。央视频7.1.1仍需独立复现分析。
