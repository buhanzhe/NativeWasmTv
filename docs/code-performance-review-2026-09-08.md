## 已修复的问题

### 1. 保存相同 DNS 配置会中断播放请求

原实现每次保存都会清空连接池并取消全部请求，但上层只有 DNS 真正改变时才重启播放，可能造成播放被中断后没有恢复动作。

现在比较归一化后的配置：相同时直接返回；真正切换 DNS 时仍执行原有失效和重建流程。

### 2. 插件能力查询提前锁定版本

原 `supportsSite()` 调用 `siteForUrl()`，后者取脚本时标记站点已经使用。仅判断频道是否支持，就可能让后续更新变成“重启后生效”。

现在共用元数据检查函数，能力查询不取出脚本、不标记使用；实际取用时才锁定版本。同时检查入口脚本是否存在。

### 3. 首次下载前反复读取不存在的目录文件

插件目录不存在时，原实现每次查询状态都会重试磁盘读取并产生异常。

现在每个进程只尝试读取一次缺失的本地目录。正常在线下载仍会直接发布新目录，能够覆盖已缓存的缺失状态。

### 4. CJS 解析重复组装源码，主线程重复计算摘要

原实现读取、写入播放结果缓存时都计算完整脚本摘要；直播列表刷新时还会重新组装相同的宿主桥接和脚本源码。

现在在加载线程中为每次频道选择准备一次缓存键和 JS 源码，刷新时复用。脚本中的网络请求仍在每次执行时运行，保证直播数据更新。脚本缓存包装对象也改为每次执行按需复用。

### 5. 旧播放列表连接滞留与关闭竞态

原接收线程读取可被清空的共享监听 socket，关闭时存在空引用竞态。已接收但尚未发送完整请求头的连接，也可能等待完整的 3 秒超时。

现在每个工作线程持有本次启动的监听 socket；关闭时同时关闭正在处理的客户端。增加启动、关闭和重新启动之间的同步保护，防止旧线程影响新监听器。

### 6. 管理网页重复状态请求与后台轮询

公共状态刷新现在最多保留一个进行中的请求，并合并为一次后续刷新。接管进度复用同一条状态读取流程，避免独立轮询与页面刷新重叠。

页面隐藏时取消公共状态请求，忽略过期回调；恢复可见时重新读取。兼容标准和旧 WebKit 的可见性事件。接管失败后的提示不会再被迟到的进度状态覆盖。

### 7. 插件更新界面的操作和显示冲突

- 更新期间禁用目录、站点更新按钮，重复点击只提交一次。
- 普通状态刷新保留正在更新的提示。
- 未保存的目录 URL 在失去输入焦点后仍保留。
- 站点列表未变化时复用现有 DOM，避免反复删除、创建按钮。
- 下载操作使用独立的 120 秒请求超时，减少被普通 15 秒界面超时误报失败的情况。
- 将目录就绪与各站点实际安装状态分别显示。

### 8. 删除和合并冗余逻辑

APK 投送与接管共用一套网段、IPv4 和端口解析，保留短 IP、完整 IP、协议和端口支持。删除 Ku9 中两段已无调用的旧辅助方法，移除 CJS 构造器未使用的布局参数。
