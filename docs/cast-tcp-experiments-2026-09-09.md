# TCP 延迟与 Wi-Fi Direct 实测（2026-09-09）

设备：MI 6 / Android 7.1.1 发送，SM-G3608 / Android 4.4.4 接收。使用 Apple TS 示例的已下载离线片段，720p、H.264、4Mbps 上限、无音频，经过生产 GL、编码器、RTSP 发送和 IJK 接收。自适应码率保持启用，因此并非恒定 4Mbps。60fps 是强制实验设置，不代表老接收端支持稳定 60fps。

## 结论

本轮没有找到可重复改善端到端 TCP 延迟的调参方案。扩大 socket 缓冲虽然减少 write 阻塞，但增加了接收延迟。压小缓冲、缩小 RTP 包、取消 Java 输出缓冲、编码前限制积压和取帧时丢弃超过 250ms 的链条均未验证稳定收益，已撤回这些实验改动。保留现有 TCP 参数、逐帧诊断字段和 RTP 线格式回归测试；不宣称 TCP 已降至 UDP 水平。

另一次 60fps 实验因写超时断开，未取得稳定接收窗口，不计为成功。调试接收探针不包含生产接管的自动重连逻辑。无线抖动和自适应码率使单轮数据有噪声，不能把某一次 P95 的降低当作稳定提升。

原参数 30fps 无截图实验：发送开始到电视读完整帧中位数约 59ms，源输出到读完整帧约 104ms，至显示提交约 131ms。该区段同时包含 socket、无线传输、接收读包和解复用，不能全部标成纯网络耗时。

## Wi-Fi Direct

两端均报告支持、已启用、权限已具备。手机普通 Wi-Fi 连接在 5180MHz，电视在 2437MHz，同名 SSID 并不等于同一频段。

- 手机组主：成功建立 192.168.49.1 组，但电视未加入，应用约 10 秒后回退普通局域网。
- 电视组主：电视成功建组并出现来自小米 6 的系统连接邀请；接受后手机仍报告 P2P-GROUP-FORMATION-FAILURE / FORMATION_FAILED，未获得 Direct 地址。
- 因此尚未建立可用双端 Direct 链路，不能提供 Direct 的 TCP 延迟数据。
- 5GHz / 2.4GHz 兼容性是下一步排查方向，尚未取得 Direct 组实际工作频率，不能认定频段就是根因。

核对另一个源码目录时发现的显示线程等待疑点不对应本轮 APK 内的原生库，未据此修改原生播放行为。

原始证据：本地 `.codex-tmp/tcp-tuning/` 下的帧日志、时钟采样、截图、frames.csv、receiver-joined.json、joined-summary.json 及两端 p2p dumpsys。实验 APK `output/release-20260909-tcp` 未通过收益验证，不作为推荐升级包。设备恢复使用此前 audio-bitrate 正式包。
