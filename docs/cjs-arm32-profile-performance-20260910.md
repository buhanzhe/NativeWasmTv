# Android 4.4：r17c 与 r25c ARM32 固定分片对比

日期：2026-09-10。设备：SM-G3608，Android 4.4.4 / API 19，ADB 8ba8ceb8。

## 方法

同一设备、同一输入分片、同一 Java 调用代码，仅替换站点 SO。停止应用播放，用 app_process 运行基准，不覆盖 APK、不修改频道数据。每站点按 base → perf → perf → base 顺序执行四个独立进程，每进程 6 次；首次调用单列，其余每档 10 次汇总。每次重置解密上下文，输入在计时前读入内存、复制，输出哈希和文件写入在计时后完成。轮次之间间隔 500ms。

本测试测量固定分片解密调用的墙钟耗时和调用线程 CPU 时间，不包括网络、插件下载、JS 接口解析、视频解码与首帧呈现。央视频使用此前固定分片测试提取的相同 HlsProxyServer 桥接流程，控制两库输入与算法调用一致。

## 结果

| 站点/编译器 | 平均 ms | 中位 ms | 范围 ms | 线程 CPU 平均 ms | 两次首次调用 ms |
| --- | ---: | ---: | --- | ---: | --- |
| 央视网/r17c | 2158.1 | 2154.0 | 2149–2179 | 2150.1 | [2137, 2117] |
| 央视网/r25c | 2140.3 | 2139.5 | 2131–2156 | 2138.9 | [2111, 2108] |
| 央视频/r17c | 1141.7 | 1139.5 | 1132–1155 | 1130.3 | [1135, 1131] |
| 央视频/r25c | 1162.3 | 1163.0 | 1149–1178 | 1149.5 | [1143, 1140] |

央视网 r25c 平均少 17.8ms（0.82%）；央视频 r25c 平均多 20.6ms（1.80%）。这台设备和这两份分片上，两档基本接近，r25c 并没有一致的加速优势。不能仅凭“性能包”命名推断提速，也不能将此结果推广为全部频道/设备结论。

库加载计时为 0–1ms（毫秒级计时，文件已通过 ADB 写入，可能命中系统页缓存），不是清空系统缓存后的冷启动基准。所有 48 次解密的站点输出哈希分别一致。
