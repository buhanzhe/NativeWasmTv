# 多媒体 RTSP 投送

## 使用

投屏与互联填写电视地址，选择图片或视频，无需先接管。手机读取文件并转码为 H.264，使用现有 TCP / UDP 选择，通过 RTSP 发送；默认 TCP。视频文件音轨独立读取，无需麦克风和录屏授权。

“保留源音频编码发送”默认关闭：音轨转为 AAC。开启时 AAC 和杜比 AC-3 直接封装发送，不经过手机音频解码、重编码。其他编码（包括 E-AC-3）当前明确提示关闭开关转码，不伪装成 AC-3，避免接收端无声。

手机需 Android 4.3+，且系统能够解码选定文件。图片保持静态画面、按 2 fps 投送；视频按设置降低帧率，当前上限 60 fps / 12 Mbps，不放大源分辨率。单文件上限 1 GB，需要相应缓存空间。HDR 转 SDR、DRM 和系统不能解码的格式不在当前支持范围内。多媒体与现有网页接管互斥。

## 实现

- HTTP 仅负责文件选取上传和会话控制；文件用 64 KiB 缓冲流式写入私有缓存，媒体通过 RTSP 传输。
- 复用 android-transcoder 的 MediaCodec/EGL 核心，无新增原生转码库。
- 编码输出最多排队 32 个包，按媒体时间戳节流，不按最快速度灌入电视。
- AC-3 使用 RFC 4184 RTP 头；UDP 大音频帧按 MTU 分片。AAC SDP 和 RTP 时钟使用实际采样率、声道数，兼容 44.1 kHz 单声道。
- 图片编码器配置 30 fps，实际输入时间戳为 2 fps，且每帧为关键帧：避开小米 6 / Android 7.1 编码器的低 fps 底层断言，确保新接收端尽快显示图片。
- 接收端复用 MainActivity / DirectVideoView 的原有投屏播放器。临时频道不写入历史，结束、断连后恢复电视自己的频道。
- 每约 0.7 秒维护一次心跳；接收端超过 3 秒未收到心跳退出。发送结束、取消、失败清理缓存，冷启动清理异常退出遗留文件。活跃发送持有 CPU / Wi-Fi 租约，退出释放。
- 旧电视缺少协议接口时明确提示更新电视端。

## 已验证

Android 7.1.1 小米 6（ff0316c7）发送、Android 4.4.4（8ba8ceb8）接收，原包名覆盖安装：

- H.264 + AAC 测试文件，完整播放 12 秒；电视日志确认 44.1 kHz mono AAC 解码。
- AC-3 原音轨发送，电视日志确认 AC-3 / 48 kHz / stereo，截图确认视频显示，硬件解码日志确认首帧。
- PNG 图片 → H.264，电视截图确认画面显示；独立 FFmpeg RTSP 解码亦成功。
- 按 25 fps 设置接收视频，实测界面约 24 fps；避免了原先 30→25 简单间隔筛选实际降到 15 fps 的问题。
- 结束后电视恢复原 CCTV-4；原有 14 项网页控制测试和主题测试通过。
- 手机浏览器 390×844 视口，新增入口和开关可见，无横向溢出。
- 强制停止发送端进程，接收端约 3.65 秒恢复原 CCTV-4（3 秒心跳判定加播放器切换时间）。正常结束后私有投送缓存目录为空；完成测试已停止双端应用。

正式包：`output/release-20260909-multimedia/nTv.apk`（32 位）和 `nTv64.apk`（64 位）；同目录保存混淆映射。两架构构建、签名及混淆检查通过，保持原包名。

未声称所有手机编码器、杜比增强格式、HDR、4K / 60 fps 均已实测。
