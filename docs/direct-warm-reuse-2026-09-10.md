# 路由器优先与 Wi-Fi Direct 复用实测

## 结果

设备：Android 7.1.1 MI6（ff0316c7）作为手机，Android 4.4.4（8ba8ceb8）作为电视。通过 ADB 覆盖安装 xiao.bu.tv，不清除数据。手机连接路由器的 5 GHz，电视连接同一路由器的 2.4 GHz；未改变网络配置。

| 场景 | 测量结果 |
| --- | --- |
| 冷连接 | 后台 Direct 升级日志 12,716 ms；脚本总耗时 13.704 s，包含系统邀请处理 |
| 正常结束后立即重连 | 路由器接管请求 0.706 s 返回；1.327 s 观察到 Direct 生效，无再次连接邀请 |
| 上述热重连后台升级 | upgradeMs = 503 ms |
| 活跃会话 | 持续超过 60 秒仍保持 Direct，闲置清理未误触发 |
| 正常结束后的清理 | 约 62 秒检查时双方 groupFormed=false、warmRemainingMs=0，手机已退出接管 |
| 后续换台 | 电视播放 CCTV8K，prepared/playing=true；IJK 日志中分片请求使用手机 Direct 地址 192.168.49.197:9966 |

这些是单次成功样本，不代表连接时间分布或所有设备均能在 2 秒内连接。冷连接的系统邀请通过 ADB 观察并点击，脚本耗时不是纯协议协商耗时。

## 实现

- 首次仍走路由器立即接管，同时后台建组、发现和验证 Direct 地址。
- 正常结束投屏后只保留已成功连接的 P2P 组 60 秒，停止发现；接管会话照常结束，电视照常恢复自己的节目。
- 重连验证同组对端的 P2P MAC、Direct 地址和协议，再复用通道，避免重复建组与邀请。
- 再次使用通道时取消闲置清理；任务代次阻止旧释放任务或发现重试干扰新会话。
- 当前会话通过认证的路由切换会更新频道解析的地址映射；旧目录无需重载，后续播放请求使用新地址。替换目录或退出接管时清空映射。
- 直接以 P2P 地址接管也取消闲置计时，修复复用后仍显示“投屏已结束”的状态文案。
- 保持现有 3 秒断线恢复规则，异常退出路径仍可立即释放组。

## 用户是否能察觉

控制通道先建立新连接、确认会话，再替换旧连接；同一频道不主动重载目录或重启播放器，减少黑屏和重复起播。

已有媒体 TCP/RTSP 连接仍保留原地址；换台或重新建立流才使用 Direct。此次没有实现一个已建立的媒体连接跨 IP 迁移，不能宣称当前媒体流已实现完全无感切换。无线协商若导致路由器网络短暂不可用，仍可能影响播放。

首次系统邀请依然可见。旧设备不能使用 API 29 才提供的 Wi-Fi Direct 网络名/密码配置接口，参见 [Android WifiP2pConfig.Builder 文档](https://developer.android.com/reference/android/net/wifi/p2p/WifiP2pConfig.Builder)。因此不承诺首次冷连接 2 秒或完全无感。
