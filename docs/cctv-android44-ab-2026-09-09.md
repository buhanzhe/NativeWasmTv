# Android 4.4 央视网 A/B 实测

2026-09-09，本地设备 `8ba8ceb8`，Android 4.4.4，32 位。比较 GitHub v1.6.0 的 nTv.apk 与 output/release-20260909-cjs-cache/nTv.apk，均为正式签名包、同一包名，保留数据覆盖安装。

使用相同央视网网页地址 CCTV-1、CCTV-2，稳定缓冲模式、high 清晰度配置、自动硬解，实际均输出 1280×720。临时测试频道排除了原列表中央视频与普通 m3u8 线路混用的问题。

## 测量结果

以设备日志中的操作标记至 `First video frame rendered` 为首帧耗时，包含指令派发的小量开销，不使用 HTTP 返回时间。切台每频道两次，按 CCTV-1、CCTV-2、CCTV-1、CCTV-2 顺序：

| 场景 | 线上 1.6.0 | 当前版 |
|---|---:|---:|
| CCTV-1 第一次 | 6.760 s | 7.550 s |
| CCTV-2 第一次 | 10.370 s | 13.820 s |
| CCTV-1 第二次 | 5.250 s | 7.360 s |
| CCTV-2 第二次 | 10.210 s | 11.820 s |
| 四次均值 | 8.148 s | 10.138 s |
| CCTV-2 冷启动（各一次） | 9.090 s | 14.740 s |

冷启动通过覆盖安装结束旧进程后点击桌面图标，保留插件与播放地址缓存；不是清空数据后的首次安装测试。当前版插件 tv.cctv.com 本地版本 1，后台检查远端也是 1。截图确认两版实际出画面，截图与原始日志保存在 `.codex-tmp/cctv-ab/`。

## 定位

- 当前版本地脚本加载 0–1 ms；非缓存的 CCTV-1 接口请求 34 ms，QuickJS 包含该请求共 45 ms。冷启动脚本执行含请求约 346 ms。
- 后续三次明确命中播放地址缓存，没有重新执行站点接口解析。仍然慢，排除了每次下载 CJS 是主要原因。
- CCTV-1 当前版启动门限：下载 440/532 ms，解密阶段 5289/5226 ms。
- CCTV-2 当前版启动门限：下载 1395/474 ms，解密阶段 11017/9810 ms。
- 旧版启动门限总计分别 4939、7924、3827、7982 ms。旧版没有独立解密分段计时，不应把这些总数直接作为旧版纯解密时间。

当前版平均慢约 24%。主要等待位于分片解密/有序处理阶段，下一步应对同一份加密 TS 分片比较内置旧库与插件 cctv.so 的执行耗时、编译优化和初始化开销。这里的 decryptMs 包含有序任务等待，并非纯 CPU 时间，尚不能据此断定某个编译参数是根因。

直播分片内容与 CDN 会随时间变化；CCTV-1 两轮还使用了不同 CDN 分片路径。样本较少、先旧后新，不能将差值全部归因于插件库。本机本次未复现旧版 2 秒启动，也不能推断 Android 9 家庭电视的绝对耗时。
