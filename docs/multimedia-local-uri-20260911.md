# 本地多媒体 RTSP 测试（2026-09-11）

发送端：Xiaomi 25019PNF3C，Android 17 / API 37；接收端：MI 6，Android 7.1.1 / API 25。使用路由器 IP、RTSP TCP。

## 修改

- 修复 multimedia.js 未进入 ControlSite 静态资源白名单导致 404、选择文件后无上传动作的问题。
- 应用内管理网页改为调用原生选择器，直接将 content URI 交给本机 MediaExtractor / 图片解码器。没有 HTTP 文件上传，也不复制整份本地文件到缓存。
- 保留外部浏览器上传流程；外部浏览器无法直接向 Android 解码器提供本地 URI。
- 手机恢复播放使用原 URI，图片流读取按采样尺寸解码。仅旧上传流程产生的临时文件会删除，用户选择的原文件不会删除。
- 选择取消、无法读取或连接失败均反馈状态。

## 实测

- 图片：通过 Android 17 系统选择器选择 PNG。日志记录 Local media URI opened without upload；7.1.1 接收 H.264 480×1072、2 fps，读取接收端解码画面确认与所选图片一致。
- 视频：通过系统选择器选择约 12 秒的本地 HEVC 2400×1080 / AAC 录屏。11:14:21.774 本地 URI 回调，11:14:22.506 接收端打开 rtsp://192.168.0.118:8554/cast，11:14:23.592 接收端报告该视频首帧硬解显示，约 1818 ms。
- 播放结束，电视恢复 CCTV-1；手机媒体状态仍为原 HEVC 文件，位置 11753 ms / 时长 12074 ms，确认原 URI 可用于恢复播放。
- 中途有一次接收端连接超时，页面有错误反馈；唤醒、恢复设备连接后重测通过。本次不是长期稳定性或音画同步测试；没有人工听音验证。

## 验证

ARM32、ARM64 release 构建通过。21 项 control-pages 回归测试通过，包括原生文件选择不产生 upload 请求。测试后两端退出应用。
