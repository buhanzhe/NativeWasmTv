# 移除输入法干预后的小米 6 飞鼠回归

2026-09-13，ff0316c7，小米 6 Android 7.1.1。当前 1.7.0 / versionCode 7，删除 WebView 输入法拦截、窗口输入法标志修改、焦点检测和自动键盘 Tab 切换后的代码。

使用现有 FlyMouseInstrumentation，通过真实 `/api/pointer` 请求注入 Android 鼠标事件，再读取系统 WebView 的 DOM 状态；本地普通控件页面不包含验证码。测试未执行优酷验证，也不能证明其验证服务会接受操作。

720p、1080p、2K、1080p + 125% 页面缩放四组均通过：

- 悬停展开、单击仅触发一次；pointerType 为 mouse，按下 buttons=1，释放 buttons=0。
- 原生 range 滑块拖至 81；普通鼠标拖动控件位移 459–460 CSS 像素，释放一次。
- 内部区域滚动、视频播放、进度拖动、全屏及返回正常。
- 取消拖动不会留下按住状态，也不会错误点击。
- 持续 1100 次 HTTP 鼠标移动共 25.6 秒，按住和释放状态正常。

首次视频进度断言失败；本地 HTTP 测试服务补上 Range 分段读取后，全套回归通过，应用代码未因此修改。

测试后已安装当前 release 包，停止应用和临时 HTTP 服务，移除测试 ADB reverse 18889。本轮没有修改频道源配置。

日志：`.codex-tmp/flymouse-711-retest.log`；截图：`.codex-tmp/flymouse-711-retest.png`。

当前触控板长按 480ms 后才发送鼠标按下；长按前开始滑动会取消长按并只移动光标。此操作区别需要向用户说明。用户所述优酷问题尚需区分直接手指触摸与飞鼠拖动，以及滑块不移动与验证结果失败。
