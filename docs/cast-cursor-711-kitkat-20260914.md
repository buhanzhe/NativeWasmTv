# 电视本地绘制投屏光标

## 行为

手机仍是鼠标坐标和网页命中的唯一来源。光标状态通过独立 UDP 通道发送给电视，
电视用原生覆盖层绘制，不经过 H.264 编码、RTSP 视频队列或解码。
归一化坐标按实际 SurfaceView 视频区域换算，保留黑边及不同屏幕比例下的命中关系。
点击动画、快速移动放大和空闲隐藏沿用原生光标。

通道端口仅通过当前互联 TCP 会话协商；数据验证对端 IP、会话标识和递增序号。
只保留最新绝对位置，不累积移动队列。收到 UDP 确认后才隐藏手机画面里的光标。
旧版接收端没有该能力、UDP 不通或确认超时，继续使用视频中的光标。
电视在 650ms 没有光标状态后隐藏覆盖层；换流、退出互联也清理覆盖层。

## 真机验证

- 发送端：小米 6 / Android 7.1.1，192.168.0.102。
- 接收端：Samsung / Android 4.4，192.168.0.113（作为电视端）。
- 使用实际 Wi-Fi 局域网连接及已配置的“工具哇”网页；1280×720，25fps，H.264/RTSP TCP。
- ADB 仅负责安装、发起测试操作和读取结果；手机到电视的光标和视频均走真实 Wi-Fi。
- 30 次移动：接收端归一化位置与手机实际光标位置全部一致。
- 手机 `cursorSuppressed=true`；电视原生光标显示，截图只见一个指针。
- 原生点击命中网页搜索输入框，down/up/drag 均收到；没有发送文本或提交搜索。
- 静止 5 秒后电视光标隐藏；退出接管后电视光标清除，手机本地绘制恢复。
- 两个平台均通过 CastCursorChannelInstrumentation：旧会话/乱序拒绝、1000 次更新合并至最后位置、确认及断开回退。

测试中的端到端观察（包含 ADB 转发的指令、探针和完整状态查询）中位数约 135ms、
P95 约 284ms，不能当作纯光标传输或屏幕显示延迟。未做高速摄影的视觉延迟 A/B。
确认的是光标已独立于视频路径，并且坐标及原生交互正确。

初次临时替换频道的组合操作被自动审批拒绝，之后直接用已有网页完成实测。
测试未修改用户的频道列表，结束后恢复本地播放；正式构建安装到两端。
