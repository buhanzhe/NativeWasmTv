# 7.1.1 手机 → 4.4 电视：直连连接耗时优化

## 后续 ADB 实测（用户要求通过 ADB 后）

已成功通过 ADB 覆盖安装到 7.1.1 / 4.4 两端，原先安装受阻的问题已解除。

首次运行进一步定位到：电视在点击后约 1.55 秒已经建组，但手机一次 owner 状态 HTTP 查询超时就提前结束升级并拆组。修复为在现有 5 秒 owner 总时限内重试 IOException；保持 LAN 会话和已建组，不因一次瞬时 STA/P2P 切换失败就清理。该修复已重新构建并覆盖安装到两端。

随后两轮均完成从 `192.168.0.113:9966` 路由器地址接管到 `192.168.49.1:9966` Direct 控制地址的自动切换：

| 项目 | 第一次成功 | 拆组后重连 |
| --- | ---: | ---: |
| ownerReadyMs（后台开始至手机确认电视组主） | 1839 | 1888 |
| routeReadyMs（后台开始至 Direct 路由探测成功） | 14404 | 11898 |
| totalMs（后台开始至控制会话切换完成） | 14439 | 11907 |
| 路由就绪后控制会话切换 | 35 ms | 9 ms |

第一次成功的路由器接管接口耗时 0.496 秒。以上完整建链时间包含系统邀请处理；邀请检测和点击由 ADB/UIAutomator 测试脚本执行，自身也有耗时，不是人工瞬时点击条件下的纯协议基准。

两次均为 4.4 电视组主 `192.168.49.1`、7.1.1 手机客户端 `192.168.49.197`。重连仍出现系统邀请，因此不能把已经连接过一次等同于无确认快速重连。2 秒完整直连目标未达到。

播放验证：电视日志在 route changed 后未出现重新创建解码器或重新首帧；ADB 截图实际有 CCTV4K 画面；`prepared=true`、`playing=true`，连续采样进度 67362 → 68939 ms，revision 保持 6。该验证支持“没有主动重复起播”，不等于测得了每帧零卡顿，也不代表已有媒体 TCP 流已迁移至 P2P。

两轮结束后通过正常退出接管接口释放会话，再 force-stop 两端 `xiao.bu.tv`。

证据：`.codex-tmp/direct-adb-retry.log`、`direct-adb-reconnect.log`、`direct-adb-phone.log`、`direct-adb-tv.log`、`direct-adb-media-before.json`、`direct-adb-media-after.json`、`direct-adb-playback.png`。

## 目标和当前结果

保留路由器 IP 首次接管，再在后台建立 Wi-Fi Direct；新地址和会话确认成功后切换。2 秒是优化目标，尚未在本轮验证为直连完成时间。

第一轮改动已覆盖安装到双方设备，实测路由器 IP 接管 0.847 秒返回成功。电视组主就绪记录为后台升级开始后 3143 ms。手机首次按地址连接返回系统 ERROR 0，随后发现重试；测试脚本在点击请求后 15.773 秒处理到系统邀请，直连最终未完成，后台耗时 14632 ms 后保留 LAN。邀请自动检查自身需要时间，这不是纯粹的 WPS 延迟测量。

后续改动去掉接管后 1.5 秒延迟、并行发现/建组并完善取消和会话校验。最终构建通过，但自动审批拦截了包含覆盖安装的命令，仅返回 blocked by policy，没有具体原因。没有重试安装；最终版本未完成实机复测。

## 改动

- 接管成功后立即排入后台直连升级，不再固定等待 1500 ms。
- Android 4.4 接收端保留电视组主兼容路径；LAN 已选定角色后立即 createGroup，去掉 8000 ms 的发现等待。
- 手机的发现过程与电视建组并行；等待电视组主就绪后按明确的 P2P 地址加入，地址连接失败再重新发现。
- 已连上同一组主时复用组，不重复发起邀请；通过组主 MAC 确认目标，避免把无关旧组误当作新连接成功。
- 取消直连后，旧任务不能继续等待、回写新任务状态或拆除新任务的组。
- 直连可用性探测使用较小的 cast 状态响应及短连接/读取超时，避免一次完整系统信息请求或网络超时耗尽连接窗口。
- 状态接口增加 `wifiDirect.upgradeMs`；日志分别记录 ownerReadyMs、routeReadyMs、totalMs 和 switched。
- 路由切换继续先建立新控制 socket、校验当前会话并等 ACK，然后才替换旧 socket。
- 同一已加载目录、同一频道/线路的路由迁移不重载目录、不重新起播。目录仍在加载或节目已发生变化时保留必要的同步。

## 无缝的范围

本次实现控制连接的先建后换，并去掉应用主动重复起播。已有媒体 TCP 连接不可能仅通过修改 URL 就迁移到另一对 IP，因此保留当前媒体流，后续换台/重建流使用 Direct 地址。这不等于当前媒体连接也已无缝迁移至 P2P。

若无线驱动在 P2P 协商时中断原 STA 网络，现有连接仍可能受影响。未放宽用户要求的 3 秒断线恢复规则。首次系统连接邀请仍需接受；没有绕过系统授权，也没有把超时时间改成 2 秒来制造连接变快的假象。

本轮设备：7.1.1 MI6 `ff0316c7` / LAN 192.168.0.114，4.4.4 `8ba8ceb8` / LAN 192.168.0.113。双方在同一 xyy-1221 路由器，手机 5180 MHz，电视 2437 MHz。未修改 Wi-Fi 凭据、包名、用户数据、路由器配置或 3 秒租约。
