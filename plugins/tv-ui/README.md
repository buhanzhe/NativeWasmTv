当前第六套主题为内置“银雾玻璃”：视频背景采样毛玻璃、银白渐变选中、黄色收藏星标。4K 等超过 1080p 像素量的视频使用渐变背景，不从解码 Surface 抓帧，避免占用播放所需的图形资源；普通视频每次打开只采样一次，抓取失败不连续重试。无需主题 JAR。以下旧插件构建说明仅供历史参考。

# 内置电视界面

六套电视界面现在全部直接编译进 APK。经典界面使用原 XML，其他五套共用 `SharedTvUi`，由 `TvUiPlugin` 直接创建内置渲染器。

主题选择沿用 `tv_ui/selected` 和原有编号，升级保留选择。`/api/tv-ui` 仅接受 JSON 主题编号，不再支持导入 JAR；APK 不再包含主题 JAR，也不创建主题 DEX 缓存。切换仍复用播放器和 Surface。

# 电视界面 JAR（API 2）

共五个离线 DEX JAR：原版 `dist/builtin.jar`，第二至五套 `ui2.jar` 至 `ui5.jar`。
构建：`python plugins/tv-ui/src/build.py`。需要 Java 8、Android SDK 的 android-30 与 D8 30.0.3。
产物同步到 `app/src/main/assets/tv-ui`，每份包含 `classes.dex` 和 `tv-ui.json`，不重复打包宿主接口。

## View 与播放分离

接口为 `xiao.bu.tv.skin.TvUi.create(Context, part, Bundle, View[], Events)` 和 `update(View, Bundle)`。
构造器由后台加载线程调用；View 创建、数据绑定与回调均在主线程。JAR 中不得在这些方法执行网络、磁盘、播放器操作。

五套界面共用 APK 内的 `xiao.bu.tv.skin.SharedTvUi`，布局、Canvas 绘制、信息卡、菜单、时钟/网速和退出框只编译一份。每个主题 JAR 只保留入口与风格编号，约 0.7 KB；原版入口约 1.5 KB。外部 API 2 View 插件仍可独立实现 `TvUi`，不强制使用公共渲染器。
公共渲染器接收宿主状态与动作；复用已有数据绑定的 ListView 控件，因此频道、收藏、节目单、鼠标/触屏与遥控器逻辑共用。
原版 JAR 的 `BuiltinUi` 使用原版 XML 资源创建列表行，并恢复原版控件。XML 资源保留在 APK，作为 Android 资源契约与插件不可用时的启动兜底。
原版仍为默认项；原版 JAR 后台加载，不阻塞启动首帧。切换界面只替换浮层，不更换 DirectVideoView、Surface 或播放器。

新界面以 960×540 为参考坐标，按视口等比缩放：第二套青色渐变胶囊与圆角侧栏；第三套蓝色矩形选择与胶囊信息卡；第四套全高无圆角菜单；第五套清透圆角、浅色焦点；第六套影院黑底与红色强调。
第二、三、四套优先保留参考图的比例和行距；第五、六套保留紧凑列表，可完整显示 10 行。
参考图来自用户的 `D:/documents/电视UI/第二套`、`第三套`、`第四套`。节目画面、广告海报不打包；第四套退出页的海报位置使用应用自己的图标与名称。
字体随 Android 系统字体栅格化，未宣称跨设备逐像素相同。

## 菜单动作

右侧分类、左侧选项；上下移动，左/右切换列，确定应用，返回先回分类再关闭。支持触屏点击与原生 ListView 滚动。

“网页管理”按本次操作方式打开：手指点击时手机进入完整网页、平板进入侧栏网页；遥控器 OK 时显示原生二维码。弹窗内的触摸和方向键/确认键会同步输入方式，避免沿用打开菜单时的旧状态。

频道分组、频道与节目单使用相同的遥控器整页规则：跨过末项立即显示下一页并选中首项，反向跨过首项恢复上一页末项；最后一页保留行高，列表首尾不循环。只有完整行参与分页，不添加可选的占位行。上下浏览不播放，OK 确认；一级、二级、三级同时只有当前操作列显示背景高亮。分组切换按频道身份记忆位置，节目单按节目开始时间恢复选择，刷新、插入、删除后保持有效落点；日期随当前节目更新。空节目单保留可返回的提示焦点，未来节目不允许播放。长按事件限速并立即处理，不积压翻页；触摸撤销分页留白并恢复普通滚动。位置记忆最多保留 64 个分组和 64 个频道，不保存到磁盘。`ChannelPagingInstrumentation` 在六套实际界面检查上述行为及缩放后的分页边界。
线路、自动/硬解/软解、原始/全屏/16:9/4:3、超时换源、时间/网速/调试显示、开机自启、反向换台、版本检查、缓存清理和退出均连接宿主真实动作。频道管理在原生菜单中提供各分组及“我的收藏”的圆形显示开关，隐藏项仍可重新开启，状态保存并与网页端的分组开关共用；隐藏收藏入口不删除收藏记录。普通分组至少保留一个可见分组。偏好设置内的“网页管理”沿用手机完整网页、平板右侧网页、电视二维码的入口。
设置通过同一个后台队列保存；异步刷新保留当前焦点。解码变化沿用宿主的播放器重建流程，单纯 UI、比例、偏好变化不重建播放器。偏好设置提供开机自启、换台反转、界面主题、唱片界面、网页管理、清空缓存和退出。屏显时间统一位于显示设置；版本菜单只保留版本与更新按钮，检查结果以 Toast 提示；“检查更新”只读取 `version-lite.json`，不回退到完整更新清单；仅打开菜单不会联网。
各主题使用相同分类和选项；偏好设置中的“界面主题”可切换原版界面、青色圆角、蓝色卡片、简洁侧栏、清透极简，不显示套数。非默认界面右侧点击打开功能设置，退出确认居中。

## 加载与性能

JAR 按 SHA-256 保存到应用私有目录并设为只读；后台校验大小、ZIP、API、入口及接口实现后用 DexClassLoader 加载。
每次 APK 更新后重新使用随包 JAR；用户手动导入的 JAR 保留。API 1 的配色插件不作为 API 2 的 View 插件加载。
加载失败保留当前界面；View 创建/绑定失败恢复原版。导入是执行可信 DEX，SHA-256 是完整性校验，不是第三方签名认证。
列表只创建可见行，复用 Bundle；无界面刷新循环、WebView 渲染、模糊位图或播放帧回调。渐变 Paint、路径尺寸等按需缓存。
时钟和网速共用宿主既有定时与流量统计。播放器浮层也是六套界面共用的宿主组件，打开频道列表立即隐藏且阻止延迟回调重新覆盖列表。
进度跳转显示加载状态；真实播放时钟恢复后消失。8 秒后说明可能较慢，25 秒后提示重试或换线路；只有收到明确请求错误才显示下载失败，不把等待等同于源站禁止跳转。

## 验证

`tests/tv-ui.test.py` 检查六份 DEX 产物、SHA、菜单选中状态及真实动作映射。
`tests/tv-ui-pages.test.js` 检查网页端选择、失败回滚与导入大小限制。
`TvUiChecks` 在 7.1 隔离测试包内验证六个 JAR、实际布局与标定尺寸、双栏联动、真实 4:3 比例、遥控器返回路径、偏好保存及焦点保持、二维码、退出操作、十二次热切换，以及 UI 配置期间播放器和 Surface 不变。五套菜单另测实际软/硬解及线路切换；慢分片和失败分片测试验证共用跳转加载提示。
截图校准期间使用测试专用中性灰 View 遮盖视频背景，播放器继续运行；结束后移除。该背景不属于正式界面，也不进入生产代码。
测试报告放在本地 `.codex-tmp/tv-ui-audit`，正式应用的数据不参与测试。

播放行的三柱图标使用宿主自绘，每 100ms 更新一次，只重绘图标所在局部区域。行不可见、临时分离、列表关闭或应用切后台时停止回调；不引入图片序列、动画库或额外播放器探测。遥控器选中项由宿主同步给行适配器，不依赖已被皮肤隐藏的系统选择框。

退出确认框显示后，再次按返回键确认退出；长按同一次返回键的重复事件不触发退出。功能设置及触摸操作保留。`ExitBackInstrumentation` 使用真实系统返回键验证六套界面，以及普通菜单返回、方向键操作和网页控制返回入口。

偏好设置提供“唱片界面”入口，直接选择经典唱片或柔光唱片。选项复用电台远程目录；JAR 仍只在下载并校验后使用，失败保留当前样式，切换不重建音频播放器。
